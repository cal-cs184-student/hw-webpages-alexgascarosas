Overview

In this homework, we implemented a cloth simulation system and several GPU shaders. The cloth system is built from a grid of point masses connected by structural, shearing, and bending springs. We then simulated the cloth using Verlet integration, external forces, spring forces, collision handling, and self-collision handling. Finally, we implemented shader programs for diffuse lighting, Blinn-Phong shading, texture mapping, bump mapping, displacement mapping, and environment-mapped reflections.

The most interesting part of the assignment was seeing how small changes in physical parameters can significantly affect the simulation. Lower spring constants and higher density make the cloth sag and fold much more, while higher spring constants and lower density make the cloth behave more like a stiff sheet. On the rendering side, it was useful to see the difference between shading effects that only change normals, like bump mapping, and effects that change the real geometry, like displacement mapping.

Part 1: Masses and Springs

Implementation Summary

we built the cloth as a num_width_points by num_height_points grid of PointMass objects in row-major order along the x-axis. For horizontal cloth, each point mass is placed at (x, 1, z), with points evenly spaced in the xz-plane. For vertical cloth, each point mass is placed at (x, y, z), where the z-coordinate includes a very small random offset in the range [-1/1000, 1/1000]. This random z-offset breaks perfect planar symmetry and helps the cloth start folding naturally.

The top-left mass is placed at (0, 0) and the bottom-right mass is placed at (width, height) in the varying plane. Pinned indices from the scene JSON are loaded into an unordered set for fast lookup. If a point mass index appears in the pinned set, that point mass is marked as pinned.

After all point masses are created, we add springs between them. This is done after construction so that pointers to point masses are stable. Structural springs connect each mass to the mass on its left and the mass above it. Shearing springs connect diagonal neighbors in the upper-left and upper-right directions. Bending springs connect masses two positions away horizontally and vertically. we also use bounds checks at the grid edges so that springs are only created between valid point masses.

Part 2: Simulation via Numerical Integration

Effects of Spring Constant ks

The spring constant controls how strongly springs resist stretching. With a very low ks, the springs barely resist stretching, so the cloth sags much deeper and looks rubbery. The Provot 10% constraint cap visibly clamps long stretches each simulation step. With a very high ks, the springs become very stiff, so the cloth barely deforms, settles quickly, and behaves more like a rigid sheet than flexible fabric.

Effects of Density

Density changes how heavy each point mass is. With low density, each mass is light, so gravity is small relative to the spring forces. The cloth sags only a little and reaches a taut rest state quickly. With high density, gravity dominates the spring forces, so the cloth sags deeply, oscillates more, and triggers the Provot correction more often. In practice, increasing density has a similar visual effect to lowering ks.

Effects of Damping

Damping controls how much velocity is removed from the system over time. With very low damping, the cloth oscillates for a long time and swings back and forth before settling. With high damping, the cloth falls more slowly and reaches its resting pose with very little oscillation.

Part 3: Handling Collisions with Other Objects

Sphere Collision Implementation

For sphere collisions, we compute the vector from the sphere origin to the point mass position. If the squared length of this vector is greater than or equal to the sphere radius squared, the point is already outside the sphere and no collision response is needed. Otherwise, we normalize the direction and compute the tangent point on the sphere surface as origin + radius * dir. The correction vector is the difference between this tangent point and the point mass's last position. we then update the point mass position using last_position + (1 - friction) * correction, which moves the point mass outside the sphere while accounting for friction.

Plane Collision Implementation

For plane collisions, we check which side of the plane the current position and last position are on by taking dot products with the plane normal. If the signs are the same, then the point mass did not cross the plane and we skip the collision. Otherwise, we project the current position onto the plane to get a tangent point, then offset it slightly along the normal using SURFACE_OFFSET to avoid numerical sticking. As with the sphere, we apply friction by moving from the last position toward the corrected target position by a factor of 1 - friction.

Collision Step in Simulation

In Cloth::simulate, after Verlet integration and before the Provot spring-length correction, every point mass is tested against every collision object. This makes sure the cloth responds to scene geometry before constraints are enforced.

Sphere Collision Results

With the default ks = 5000, the cloth drapes smoothly over the sphere with moderate folds on the sides, which gives a typical fabric-like result. With ks = 500, the springs are much softer, so the cloth stretches more under gravity and hangs lower around the sphere. With ks = 50000, the springs are very stiff, so the cloth stretches less and the creases stay sharper instead of smoothing out.

Part 4: Handling Self-Collisions

Implementation Summary

To handle self-collisions efficiently, we first divide space into hash buckets. In hash_position, we use box dimensions based on the cloth dimensions and number of point masses: w = 3 * width / num_width_points, h = 3 * height / num_height_points, and t = max(w, h). The point mass position is converted into a box index, and the x, y, and z indices are combined into a single hash key using a polynomial-style hash.

In build_spatial_map, we clear the old map and insert every point mass into the bucket corresponding to its hashed position. Then, in self_collide, we only compare a point mass against other point masses in the same bucket. we skip the point mass itself, and for each nearby candidate within 2 * thickness, we compute a correction that pushes the two masses apart. All corrections are averaged, divided by simulation_steps to soften the response, and added to the current point mass position.

In Cloth::simulate, we build the spatial map once after Verlet integration, then call self_collide on every point mass before handling primitive collisions. This lets the cloth separate from itself as it falls and folds.

Effects of Varying ks

With low ks, such as ks = 5, the springs are extremely soft, so the cloth offers almost no resistance to compression. The folds are smaller, noisier, and more wrinkled rather than forming large smooth layers. With high ks, such as ks = 10000, the cloth is stiffer, so it forms fewer but larger and smoother folds. The fold edges look sharper and the pile is taller because the fabric resists compressing into itself.

Effects of Varying Density

With low density, such as density = 1, the cloth is light relative to the strength of the springs. It falls more gently and folds into cleaner, more regular cylindrical layers, similar to increasing ks. With high density, such as density = 100, the cloth is much heavier and overpowers the springs. It slams into the plane and piles into a more chaotic crumpled shape with many small overlapping folds, similar to using a low spring constant.

Part 5: Shaders

Shader Programs

A shader program is code that runs on the GPU to control how objects are drawn. In this homework, each shader program is made of a vertex shader and a fragment shader. The vertex shader runs once per vertex and transforms positions, normals, tangents, and UV coordinates into the spaces needed for rendering. The fragment shader then runs once per fragment and uses the interpolated values from the vertex shader to compute the final color. Together, these shaders create lighting and material effects such as diffuse shading, specular highlights, texture mapping, bump mapping, displacement mapping, and mirror reflections.

Blinn-Phong Shading

The Blinn-Phong shading model combines three lighting terms: ambient, diffuse, and specular. Ambient lighting is a constant base light that keeps the object from being completely black. Diffuse lighting depends on the angle between the surface normal and the light direction, so surfaces facing the light appear brighter. Specular lighting creates shiny highlights using the halfway vector between the view direction and the light direction. The full Blinn-Phong model adds all three terms together to create a more realistic material.

Texture Mapping

For texture mapping, we used the UV coordinates passed from the vertex shader to sample from a 2D texture in the fragment shader. Instead of computing the color only from lighting, the shader reads the color from the texture at the current fragment's UV coordinate. This allows an image to be wrapped onto the surface of the cloth or sphere. we replaced the default texture with my own custom texture to confirm that the UV mapping was working correctly.

Bump Mapping and Displacement Mapping

Bump mapping and displacement mapping both use a height map, but they affect the surface differently. In bump mapping, we changed the normal vector used for lighting based on the height map. This creates the illusion of bumps and grooves, but the actual geometry does not move. Because of this, the silhouette of the object stays smooth.

In displacement mapping, we changed the actual vertex positions using the height map. Vertices are moved along their normal direction based on the sampled height value. This changes the real geometry of the mesh, so the surface and silhouette can physically deform. Displacement mapping looks more realistic when the mesh has enough resolution, but it depends heavily on mesh density.

Mesh Coarseness Comparison

When the sphere mesh is coarse, using -o 16 -a 16, displacement mapping looks blocky because there are not enough vertices to represent the height map smoothly. The bumps are limited by the low number of triangles. When the sphere mesh is dense, using -o 128 -a 128, the displacement becomes much smoother and more detailed because there are many more vertices available to move.

Bump mapping reacts differently because it does not move vertices. It only changes the normals used for lighting, so the effect can still look detailed even on a lower resolution mesh. However, since the geometry is unchanged, the outline of the sphere remains smooth and does not show real surface deformation.

Mirror Shader

For the mirror shader, we computed the view direction from the surface point toward the camera, reflected that direction around the surface normal, and used the reflected direction to sample from a cubemap. This approximates mirror-like reflection by using the environment map as the reflected scene. The shader does not trace real reflection rays through the scene, but it gives a convincing reflective material effect.

Custom Shader

We did not implement an additional custom shader beyond the required shaders. The main shader effects we implemented were Blinn-Phong shading, texture mapping, bump mapping, displacement mapping, and environment-mapped mirror reflection.
